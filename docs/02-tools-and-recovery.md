# 02｜开始之前：准备工具，学会保存和回退

> **本章任务**：把写代码、打开项目、检查结果的工具准备好，还要知道改坏了怎么退回去。  
> **准备材料**：你的电脑、已经拿到的项目文件，以及项目附带的安装说明。有多少先拿多少。  
> **本章产出**：一份能照着启动项目的记录，还有已经试过的保存和恢复办法。  
> 不用现在把所有工具装齐。还没用到的东西，先别急着装。

## 保存文件，为什么还不够？

<!-- teaching-figure:02-1 -->

![① 连续修改之后，想回到原来。覆盖保存不是版本记录。](/images/lessons/02-scene-1.png)

*图解：覆盖保存不是版本记录。 [查看大图](/images/lessons/02-scene-1.png)*

AI 修一个报名报错，改了十几个文件。你试了一下，报名好了，名单页面却打不开了。

你想回到改之前，才发现每次都直接保存，原来的文件已经被盖掉了。你记不住原来写了什么，AI 也未必能准确还原。

像修改一张照片：你把原图盖掉了，又没留副本，后来觉得修过头了，就找不到最初那张。

**所以，动手之前先回答一个问题：这次改坏了，我准备从哪里退回去？**

## 第一步：区分三种环境

这里说的“环境”，就是项目正在使用的电脑、工具、设置和数据。比如同一个外卖软件，练习时用假订单，真正营业时用真实订单，不能混着改。

| 你现在在哪儿做事 | 是干什么用的 | 要注意什么 |
| --- | --- | --- |
| 本地开发，也就是在自己的电脑上做 | 写代码、试功能 | 尽量用编出来的名字和记录，别拿真实数据练手 |
| 共享测试，也就是给大家一起试的地方 | 检查能不能一起正常用，演示给甲方看 | 别随便清空，里面可能有正在检查的内容 |
| 正式环境，也就是真正对外使用的地方 | 处理真实报名和其他业务 | 改之前要有明确同意，还要想好出事怎么恢复 |

**别只看程序开在哪台电脑，要看它连到哪里。**

数据库可以先理解为项目存记录的地方。例如网购订单的编号、金额、退款状态，都可能存在里面。

即使程序开在你的电脑上，只要连着正式数据库，点一次删除也可能删掉真实记录。好比你在自己的手机上操作，照样能把云相册里的照片删掉。

拿到项目先确认：正在用哪份数据？点按钮会改哪里？不清楚就先不操作会改数据的功能，找资料或找懂的人确认。

## 第二步：准备最小工具集合

先把下面几样的用途弄清楚，不必每类装三四个。

- **跟 AI 干活的工具**：能聊天，开发时还能按你的允许查看、修改项目文件。
- **看文件的工具**：能打开代码，搜索文字，比较修改前后哪里不同。
- **运行环境**：让代码跑起来需要的软件。比如某个项目要求某一版 Node.js，就先按它的说明准备，别把所有语言都安装一遍。
- **Git**：帮代码记住历史的工具。例如今天报名能用，明天改坏了，可以查昨天留下的那一版。
- **检查结果的工具**：至少能打开网页、看到报错，并按项目说明执行检查。

你后面会看到“日志”这个词，它就是程序留下的运行记录。例如“几点收到提交、在哪一步报错”，像快递的运输记录一样，能帮助你往回找问题。

AI 说“我会检查”，你还要看它到底能不能打开网页、能不能运行项目。只在聊天里列出检查步骤，不算真的检查过。

安装失败也别马上让 AI 把所有东西升级一遍。先保留错误原文，看看项目要求什么版本、你实际装了什么。否则可能为了修一个安装问题，又弄出好几个不兼容的问题。

## 第三步：认识 Git、备份与数据库的区别

<!-- teaching-figure:02-2 -->

![② 代码回退，不会恢复数据库。分别保护代码、配置、数据和上传文件。](/images/lessons/02-scene-2.png)

*图解：分别保护代码、配置、数据和上传文件。 [查看大图](/images/lessons/02-scene-2.png)*

Git 能把代码的某个样子记下来，这个动作叫“提交”。比如你试过报名能用，就留一条“报名提交和查询已检查”的记录，以后能找到它。

但它不会自动帮你保住项目里的所有东西。

| 要保住什么 | 怎样做 | 最容易想错的地方 |
| --- | --- | --- |
| 代码 | 用 Git 留下已经检查过的一版 | 文件点了保存，不代表 Git 已经记下这次修改 |
| 项目设置和密码 | 按项目约定另行妥善保存 | 不能因为方便就和代码一起公开 |
| 报名等业务记录 | 单独备份数据库，并试着恢复 | 把代码退回昨天，今天删掉的记录不会自己回来 |
| 上传的图片和文件 | 另外确认存放位置和备份 | 它们可能根本不在代码文件夹里 |

“备份”就是另外留一份可以找回的副本，像把手机照片再存到另一处。只留了照片缩略图，却没留原图，就不能算照片已经保全；项目备份也要看清楚到底包含什么。

“密钥”可以当成程序使用的密码。例如调用付费服务时，服务会靠它认出你的账号。发到公开地方后，别人可能花你的钱，所以不要把真实值交给 AI，也别写进公开示例。

第一次让 AI 帮你用 Git，先让它看：现在是不是正确的项目？有哪些改动还没保存到 Git？有没有你不认识的文件？**别一上来就让它“清理干净”。**

你可能还会遇到“分支”，可以理解成在原来代码旁另开一条修改路线。例如想尝试新的页面做法，可以先在另一条路上试，不马上影响原来的那条。它仍然不能代替数据备份。

有些文件本来就不该放进代码历史，例如真实密码、临时文件和下载来的工具包。先让 AI 解释准备保存哪些文件，你看过之后再做。不要只因为它列了一大串命令，就从头执行到尾。

**提示词示例：**

仅作为示例，不建议作为实际项目中的提示词使用。

> 我想先把现在的代码保护好，免得后面改坏了找不回来。请先看看是不是正确的项目文件夹、Git 记下了哪些文件、还有哪些修改没记下来。暂时不要改文件，也不要删除、提交或上传。先解释现状，再说最少需要做哪几步，每一步会影响什么。

如果密码已经被发出去了，只删掉那行文字不够。就像银行卡密码泄露后，不能靠删聊天记录解决，需要更换或停用旧密码，并查有没有被使用。

## 第四步：先练习一次恢复

<!-- teaching-figure:02-3 -->

![③ 备份之后，在隔离环境恢复一次。能恢复，才是可用的恢复方案。](/images/lessons/02-scene-3.png)

*图解：能恢复，才是可用的恢复方案。 [查看大图](/images/lessons/02-scene-3.png)*

别拿真正的项目第一次练。另建一个练习文件夹，放一个无关紧要的文本文件，写上“第一版”。

让 AI 带你把这一版记到 Git，再改成“第二版”，看看前后差在哪儿，最后试着恢复成“第一版”。每做一步，都打开文件看看结果。

你要弄懂的是：退回后是什么？刚加的新文件会不会还在？没有记到 Git 的文字会怎样？不清楚就先问，别拿正式项目碰运气。

数据库也要单独练。可以用一份专门练习的数据做备份，再恢复到另一个专门练习的数据库，看看记录数量、报名状态是不是还对。**不要把练习恢复的目标选成正式数据库。**

这就叫“隔离”：练习用的东西不和正在使用的东西混在一起。像在备用手机上试恢复相册，别直接覆盖唯一那台手机的照片。

**有备份文件，不等于一定救得回来。** 可能备份不完整，可能打不开，也可能漏了上传的图片。要实际恢复一次，才知道还缺什么。

## 第五步：为 AI 设置当前阶段权限

“权限”就是允许它做什么。例如可以看文件，但不能删除；可以改练习项目，但不能碰正式数据。

刚开始了解项目，可以只让它看。准备写代码时，再允许它改这次要做的那部分。要删除数据、增加付费服务，或者影响已经在使用的功能，就先把原因和后果说清楚，再决定。

光在提示词里写“别误删”不够。工具本身能限制文件夹和操作范围的话，也要设好。像手机备份，口头说别删照片，和真的留好副本，是两回事。

也别每次弹出确认都不看就点同意。先看它要动哪个文件、连哪份数据、会不会花钱。看不明白时暂停，让它解释或去找懂的人问。

## 做一份简短环境记录

不用写成正式报告，能让你下次照着打开项目就行：

- 项目文件在哪个文件夹。
- 需要装哪些软件，分别是哪一版。
- 怎样安装、怎样启动、从哪个地址打开。
- 怎样检查主要功能，报错去哪里看。
- 有哪些设置要填，去哪里获取，别直接写真实密码。
- 练习数据从哪里来，备份放在哪儿，恢复做过没有。

以后找人帮忙，把这份记录和完整报错一起带上。少一句“反正启动不了”，多说一句“按说明做到第几步，出现了哪段错误”，对方才知道从哪里看。

## 完成检查

- [ ] 知道程序实际在用哪份数据，不只知道网页地址。
- [ ] 能按记录启动项目，知道报错去哪里看。
- [ ] 重要改动前留了能找到的旧版代码。
- [ ] 知道代码退回去，不会自动找回数据库和图片。
- [ ] 真实密码和数据没有被放到公开地方。
- [ ] 已在练习文件夹试过恢复，没试过的部分也如实记下了。

**练习：** 网购软件的代码退回昨天，今天误删的订单却没回来。这正常吗？想一想，你应该找哪份备份，而不是继续把代码往前退。

## 卡住了怎么办？

工具装不好，可以先保留错误，去问有相关经验的人。说明你做到了哪一步、装的是哪一版、已经试过哪些办法，别把带密码的设置文件整个发出去。

暂时跑不起来，也可以先继续问需求、画页面草图。把没做完的准备记下来就行，没运行过的检查不能写成“通过”。
